============================================================

vault-sync

Payload minimal:

{
	"vault_commit": "...",
	"vault_branch": "main",
	"repo_clone_url": "https://github.com/aryandaa/Obsidian-Vault.git"
}

Workflow ini TIDAK boleh melakukan parsing.

Workflow ini hanya memberi tahu website:

"Vault baru saja berubah. Gunakan commit ini untuk melakukan sync."

============================================================
10. WEBSITE SYNC WORKFLOW
============================================================

Website repository harus memiliki:

.github/workflows/sync-docs.yml

Workflow menerima:

repository_dispatch

event:

vault-sync

Juga sediakan:

workflow_dispatch

sebagai manual recovery.

Tidak perlu scheduled polling.

Jangan membuat cron setiap beberapa menit.

Workflow:

1. menerima payload
2. mendapatkan commit SHA
3. mendapatkan branch
4. clone vault ke temporary directory
5. parser membaca temporary clone
6. parser menghasilkan generated/
7. validasi hasil
8. publish generated ke public/
9. menghapus stale generated files
10. commit hanya generated public artifacts
11. cleanup temporary vault clone

============================================================
16. STABLE DOCUMENT ID
============================================================

Primary ID harus berasal dari normalized vault-relative path.

Contoh:

Pemrograman/PHP/Framework/Laravel/Routing.md

menjadi:

pemrograman/php/framework/laravel/routing

Contoh:

{
	"id": "pemrograman/php/framework/laravel/routing",
	"relativePath": "Pemrograman/PHP/Framework/Laravel/Routing.md",
	"slug": "routing"
}

id adalah identity.

relativePath mempertahankan casing asli.

slug hanya identifier human-friendly.

Jangan menggunakan slug sebagai identity utama karena slug dapat bentrok.
